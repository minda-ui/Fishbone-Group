## Why this happened, and why it was not a platform limit

Every session that changed the record added a dated note to the top of `current-state.md` and left the
previous ones in place. That is a running log, and the file's purpose is a **present snapshot**. The same
failure has been caught twice before in this KB — the `Hub requests raised` row on 2026-09-20 and the
`Next action` row's AGGA narrative on 2026-09-21, both moved out for exactly this reason — and the header
was doing it in plain sight the whole time.

**The prompt was somebody else's work.** Alex and Eugene both split their charters on **2026-09-23**, the
same day, for the same stated reason: a governed file should be divided by **how often a part changes**, not
by what it is about. Under archive-then-recreate the cost of an edit is the size of the **whole file**, so
what should decide where a passage lives is **churn, not subject**. Alex's `Charter-History.md` names the
cost directly: *"the base64-relay corruption hit twice earlier this same week on files this size"* — 25–28 KB
files, from a second seat, independently. That is the strongest corroboration `RA-31` has had.

**The measurement that made it obvious:** Alex's own `current-state.md` is **6,503 bytes**. This one was six
and a half times that, and not because Finance is bigger — because it was carrying its own history.

## The `RA-32` prevent control, finally

`RA-32` has recorded four defects in two days, every one caught by a **detect** control (the byte check or the
read-back) and none prevented. All four came from the same reflex: a long emit, a passage being re-read, and a
correct improvement written straight into the write.

**This move was done programmatically — split by block index, nothing retyped.** That is the prevent control:
a restructure that *cannot* be mis-composed, because no hand copied the text. It generalises — any move of
existing content between files should be a mechanical extraction, never a re-typing. Recorded on `RA-32`.
